# FdF — каркасная 3D-модель карты высот

![Окно приложения на карте peak.fdf](docs/screenshot.png)

## Описание

Приложение читает прямоугольную таблицу высот `.fdf`, строит изометрическую
проекцию и соединяет соседние точки каркасной сеткой. Реализованы обязательная
часть и все шесть дополнительных направлений из задания: масштаб и сдвиг,
изменение высоты, вид сверху, изменение угла, цвет, конфигурация CI.

Графическая библиотека — стандартная `tkinter`; она импортируется только в
`fdf/app.py`. Для запуска дополнительные пакеты Python не нужны.

**Статус проекта**. Исходный код опубликован на
[GitHub](https://github.com/mxskxm/fdf-python.git).
Автоматическая проверка Quality успешно выполнена в GitHub Actions.
Стартовый набор и его `tests/test_public.py` не были приложены: здесь собственные
тесты, их нельзя выдавать за публичные тесты преподавателя. Совместимость с
непредоставленными сигнатурами не подтверждена.

## Установка и запуск

Для скачивания через Git выполните:

```bash
git clone https://github.com/mxskxm/fdf-python.git 
cd fdf-python
```
Если проект скачан ZIP-архивом, распакуйте его целиком и откройте терминал
в папке, содержащей main.py и requirements-dev.txt.

Далее выполните команды установки и запуска для своей системы.

Windows PowerShell:
```bash powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe main.py maps/peak.fdf
```

Если установлен более новый Python, замените `py -3.12` на `py`.
Использование полного пути к Python позволяет обойтись без активации окружения.

Linux или macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python main.py maps/peak.fdf
```

Проверить наличие tkinter можно командой `python -m tkinter` с тем же
интерпретатором. Если модуль отсутствует, установите поддержку Tk для своей
установки Python. В окружении без графического экрана программа выведет
диагностику и завершится с кодом 1.

## Управление

Для букв и скобок используйте английскую раскладку; окно должно иметь фокус.

| Клавиша | Действие |
| --- | --- |
| Esc или крестик | Завершение работы |
| Колесо мыши | Масштаб относительно текущего центра модели |
| Стрелки | Сдвиг на 20 пикселей |
| + или = / − | Увеличить / уменьшить коэффициент высоты на 0,2 |
| T | Переключить вид сверху и изометрию |
| [ / ] | Изменить угол осей на 5 градусов, диапазон 0–80 градусов |
| R | Восстановить исходную камеру и вписать карту |
| Изменение размера окна | Заново вписать и центрировать карту |

Изменение высоты, угла и вида также заново вписывает карту. Изменение `angle`
меняет угол изометрических осей по формуле задания, это не произвольное
вращение трёхмерного объекта. Коэффициент высоты ограничен диапазоном 0–100.

## Формат карты

Строка — координата `y`, номер значения — `x`, значение — высота `z`.
Координаты модели начинаются с 0. В диагностике номера строк и значений
начинаются с 1. Колонка в сообщении — номер значения, не номер символа.

```text
0 0 0 0 0
0 2 2 2 0
0 2 5,0xFF0000 2 0
0 2 2 2 0
0,0xff 0 0 0 0
```

Все строки одинаковой длины. Пустые строки в конце игнорируются, внутри карты
не допускаются. Высоты — целые десятичные числа, в том числе отрицательные.
Цвет — `0x` и от одной до шести шестнадцатеричных цифр, например `0xff`.
В модели он хранится как `#0000FF`; отсутствие цвета — `None`.
Точки без цвета окрашиваются по высоте; вдоль рёбер используется градиент.
Файл читается как UTF-8, допускается BOM.

`maps/elem.fdf` — основная карта 5×5; `flat.fdf` — плоскость;
`peak.fdf` — явные цвета и короткая запись; `negative.fdf` — отрицательные
высоты; `single.fdf` — одна точка. Ошибочные примеры находятся в `maps/bad/`.
Карты созданы для этой реализации, это не исходный комплект школы 42.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `main.py` | Аргументы, stderr, коды возврата 0, 1, 2 |
| `fdf/errors.py` | FdfError и MapFormatError |
| `fdf/model.py` | Point и Map, обход и соседи |
| `fdf/parser.py` | parse_map и parse_value |
| `fdf/projection.py` | Camera, lerp_color, height_color |
| `fdf/app.py` | App, окно Tk, события и рисование |
| `tests/` | Тесты парсера, модели, проекции, цвета и CLI |
| `.github/workflows/ci.yml` | ruff, mypy и pytest при push и PR |
| `docs/` | Снимок работающего приложения и инструкция GitHub |

API модели: `Map(list[list[Point]])`, `map[y][x]`, `map.get(x, y)`,
`map.neighbors(x, y)`. `len(map)` — число всех точек, `for point in map`
обходит их построчно. `neighbors` возвращает только правого и нижнего соседей.
`Camera.project(point)` возвращает пару чисел, `Camera.fit(map, width, height)`
изменяет масштаб и смещения на месте. `angle` задаётся в радианах.

## Тесты

После установки зависимостей:

```bash
python -m pytest -q
python -m mypy --strict fdf main.py
python -m ruff check .
```

В Windows вместо `python` можно подставить `.venv\Scripts\python.exe`.
Зафиксированная проверка: **58 тестов проходят**, mypy проверяет 7 исходных
файлов без ошибок, ruff не выдаёт замечаний. Отдельно проверено настоящее
окно: отрисовка, масштаб, сдвиг, высота, вид сверху, угол, сброс,
изменение размера, Esc и отображение одной точки. GUI не включён в pytest.

GitHub Actions автоматически запускает ruff, mypy и pytest при отправке
изменений и создании pull request. Результаты доступны на вкладке
[Actions](https://github.com/mxskxm/fdf-python.git).

Для N точек и E рёбер вычисления занимают O(N + E), память — O(N + E)
с учётом элементов Canvas; градиент делит разноцветное ребро на 12 отрезков.
Tk Canvas подходит для учебных карт. На очень больших картах (например,
500×500) миллионы элементов Canvas могут приводить к задержкам и расходу памяти.
